# Manual capture geometry diagnostics

The README media capture is opt-in through `workflow_dispatch` on the canonical repository's `main` branch. Routine CI runs safety, geometry, release-fixture, and synthetic-fixture isolation tests only; it does not capture screens or launch the published app. The isolation test launches only a no-UI probe bundle that reads defaults and never touches the pasteboard.

## What run 36270162668 proves

The failed run on September 26, 2026 identified a Clipboard Shelf status-bar item, then failed to find exactly one visible app-process window satisfying the existing adjacency predicate after 12 polls. The log does not include the candidate window frames or a more specific rejection. The capture helper suppressed `menu_geometry` stdout/stderr in the polling loop and ignored per-window accessibility-query errors. The run predates failure-only geometry artifacts, and GitHub reports no artifact for that run. Therefore the precise cause—missing AX windows, inaccessible geometry, zero qualifying candidates, or ambiguous candidates—remains **unproven**. Do not describe a guessed cause as a fix.

### Likely mechanism, reproduced with a synthetic fixture

Experiment run `36280841525` launched a fixture built like Clipboard Shelf's menu-bar UI: a square `NSStatusItem` with a paused accessibility description and a transient `NSPopover`. It ran on the same `macos-26` image (26.6.2, 1024×768 at 1×) and on `macos-15` (15.7.9). The status item was found by PID and exact description, in `menu bar 1`, and clicking it opened the popover, as the fixture itself confirmed. System Events still reported **zero windows** for the process, and the original `menu_geometry` AppleScript, extracted verbatim, failed with the same error as run `36270162668`. The popover appeared only in CGWindowList, owned by the fixture PID at layer 25 (for example `546,26 456×526` below a status item at `762,3 24×24`), where the unchanged adjacency predicate selects it uniquely. This shows the old selector cannot see an `NSPopover` on these images. It was not reproduced with the published app, which routine CI must not launch, so treat it as the likely cause, not a verified fix, until a capture is authorized.

## Fail-closed changes in this PR

- Select popover geometry by PID. `readme-media-status-item.applescript` finds the status item in the launched PID's menu bars by the exact, case-sensitive description `Clipboard Shelf — recording paused`. It swallows no accessibility errors, so a failed query fails the call, and the paused-only description also shows the app read the paused fixture. The popover is chosen from that PID's complete CGWindowList inventory; `windows-pid` rejects any incomplete record rather than skipping it. `select-popover` applies the adjacency predicate to every visible window the PID owns. `verify-status-popover-geometry.sh` checks this against two copies of a synthetic fixture with the same description. Before the click, selection must fail with `no_adjacent_app_window`, and a case-changed description must match nothing. After clicking copy A, geometry must equal the popover frame AppKit reports, while copy B still finds no popover. That shows selection is bound to the PID, not to whatever popover is on screen.
- Keep the original adjacency thresholds unchanged: horizontal overlap within 80 points, vertical gap from -8 through 120 points, and minimum window size 240×240 points. Revalidate measured status-item/popover geometry before capture and reject missing, invalid, off-display, or ambiguous candidates.
- Read and validate the PNG pixel dimensions from each still capture, requiring an exact match to measured region bounds multiplied by display scale. A missing, malformed, or mismatched image fails the capture.
- Pin the published `v1.0.2` release tag to commit `f25223855444d19e204016e27b8940afec806b20`, archive `Clipboard-Shelf-1.0.2.zip`, and SHA-256 `ed25cf9e18a6b268ec802f63c16e469ccbece92558760a14413b66585233312f`. Verify the release asset digest/sidecar plus bundle identifier/version/executable before extraction or quarantine removal.
- Pass the exact synthetic Shelf history and paused-recording flag to the launched app only as `NSArgumentDomain` launch arguments (`open -n "$APP" --args -ClipboardShelfHistoryV1 <data> -ClipboardShelfRecordingPausedV1 YES`). Launch arguments are never persisted. The capture refuses to launch if the real `local.clipboardshelf` domain exists, where only an explicit "does not exist" answer from `defaults` counts as absent. On exit it SIGKILLs every process running the extracted executable, because a normal quit runs the app's `saveHistory`, and fails if any instance survives. It then fails if the real domain holds any key other than AppKit's own `NSStatusItem Preferred Position|Visible|VisibleCC …` bookkeeping, logging key names but never values. Menu-bar app launches can create those keys, and the fixture check reports their names on each runner. The published app's `NSPasteboard` polling checks pause before reading clipboard text.
- The capture job runs both macOS checks (`verify-clipboard-demo-isolation.sh`, `verify-status-popover-geometry.sh`) on its own `macos-26` runner immediately before capturing. Routine macOS CI runs them on `macos-15`. Neither launches the published app or captures the screen. If a job is cancelled, GitHub can kill the job before the `EXIT` trap runs, and the app, started through LaunchServices, is outside the job's process tree; only the ephemeral runner VM contains that case.
- This repository captures only Clipboard Shelf: the script exits for any other `APP_KEY`, whose shared paths do not meet these isolation rules.
- Clipboard Shelf no longer records the GIF/MP4 hero. Its animation pinned and clicked rows, which makes the app save history into the real preference domain and write to the system pasteboard. The owner has confirmed GIF/MP4 deliverables are not needed.
- Snapshot the runner's dark-mode setting before any appearance change and restore it from the `EXIT` trap on every success and failure path; a failed restore fails the run.
- Keep captures, temporary release files, and logs under `$RUNNER_TEMP`. A successful artifact upload lists only the two Clipboard Shelf stills. The Clipboard Shelf path does not generate a composed social preview.
- Remove desktop modifications, Finder restarts, Finder and Terminal window closes, and broad `system_profiler` output.
- On failure, upload only a short-retention JSON geometry snapshot containing the status-item match/frame, launched app PID, that PID's window IDs/layers/bounds/alpha, display geometry, and allowlisted reason/error codes. It excludes window titles, clipboard text, unrelated processes, screenshots, and credentials.

## Preference isolation evidence

Earlier heads seeded the fixture with `CFPreferencesSetAppValue` under `HOME`/`CFFIXED_USER_HOME` set to a `$RUNNER_TEMP` directory, and CI then failed because no plist appeared there. Experiments on `macos-15` (15.7.9) and `macos-26` (26.6.2) runners (runs `36280230399` and `36280457801` on the throwaway `claude/laughing-hawking-r22xe6` branch) established why:

- `cfprefsd` ignores `HOME` and `CFFIXED_USER_HOME`. The fixture was written to the runner's real `~/Library/Preferences/local.clipboardshelf.plist`, `defaults read local.clipboardshelf` returned it, and the verifier passed with no isolation at all. The old CI check was right to fail. On a non-ephemeral Mac, the capture would have overwritten a real user's history.
- `__CFPREFERENCES_AVOID_DAEMON=1` does not isolate either. It still wrote to the real home, and it persisted the history key while dropping the paused key.
- `defaults delete` leaves an empty plist behind, so writing and then cleaning up is not isolation.

`verify-clipboard-demo-isolation.sh` (macOS CI) replaces the plist-path assertion. It builds a probe bundle with the app's identifier, launches it through LaunchServices with the capture's exact launch arguments, and requires the exact paused fixture: counts plus a SHA-256 digest, with no clipboard text written. It then relaunches the probe without the arguments and requires `history=absent` (negative control). It requires the real domain to be absent before and after. Run `36280767842` confirmed the check on both runner images. On a clean runner it passes. When the legacy `ee736fe` seeding is planted first, it fails on the real-domain precondition. With that precondition removed, the negative control still fails, because the probe reads the leaked fixture without arguments.

Deterministic fixtures cover the existing strict geometry boundaries, absent/ambiguous candidates, the runner-observed window inventories, malformed PNGs, and exact pixel-size mismatches. The PNG check validates the file's structure. It requires exactly one IHDR first, a valid colour-type/bit-depth pair, a PLTE before the image data for palette images, one run of consecutive IDAT chunks, and an empty IEND last with nothing after it. Every chunk CRC must match. The declared size is compared with the expected size before any decompression. The IDAT stream must then decompress, with nothing left over, to exactly one valid filter byte plus the packed row bytes for every scanline. Filters are not reversed, so pixel values are not inspected. None of this reconstructs the missing geometry from run `36270162668`.
